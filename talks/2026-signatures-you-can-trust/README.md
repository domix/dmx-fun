# From exceptions to signatures you can trust

45-minute talk for Java user groups. Tracked in [issue #561](https://github.com/domix/dmx-fun/issues/561).

```bash
cd talks && pnpm install
pnpm dev          # opens the deck; press L to switch EN/ES, D for light mode
pnpm build        # static site in 2026-signatures-you-can-trust/dist
pnpm export       # deck-en.pdf and deck-es.pdf (playwright-chromium is a dev dependency; pnpm install downloads its browser)
pnpm demo:play    # the recorded demo, in the terminal; pnpm demo:record re-records it (needs the sample running)
```

## Two languages, one source

- Short sentences on slides use `<T en="…" es="…" />`.
- Longer passages use `<Tk k="…" />` with the text in `i18n/en.json` and `i18n/es.json`.
- Speaker notes carry both languages, prefixed `EN:` and `ES:`.
- `scripts/check-i18n.mjs` runs before `dev`, `build` and `export`; it fails when a sentence exists in only one language.
- Open with `?lang=es` to start in Spanish; `L` toggles live; the choice is remembered in the browser. `VITE_DECK_LANG` sets the default for exports.

## Code on slides

Every snippet is imported from the compiled, tested sources in `samples/enrollment-tutorial` with
`<<< @/snippets/<path>#region`. The regions are `// #region name` … `// #endregion name` comments in the
Java files. Slidev only imports from inside its workspace, so `scripts/sync-snippets.mjs` copies the
files listed in `snippets.json` into `snippets/` (git-ignored) before every `dev`, `build` and `export`.
To show new code: add the region to the source and the file to `snippets.json`; never paste code into the deck.
The exceptions are the illustrative `findUser` signatures on the hook and closing slides and the five quoted
signatures on the recap slide, which are kept in step with the tutorial chapters by hand.

## Structure

28 slides: naming and the three gaps the library fills, the hook, chapter 0 from both sides, return instead of throw,
railway, all the errors at once, integrations, out the door (status, metrics, the controller, transactions, the demo and its recording),
start at one boundary, open source and four ways in, a five-line recap, the closing, a Q&A appendix, and a farewell slide with the library's and the speaker's details.
Speaker notes carry the minute marks from the outline in issue #561. After each delivery, fill a section in
`DELIVERIES.md` (questions asked, timing, what to change); that is what feeds the deck and the tutorial afterwards. `demo.md` has the commands for the demo block;
`demo.cast` is its recording, played on the slide after the demo table through `components/Cast.vue` (asciinema-player).

The QR codes on the closing slide are SVGs in `qr/`, generated by `pnpm qr` (`scripts/make-qr.mjs`); rerun it if a URL changes.
